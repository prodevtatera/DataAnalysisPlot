# Phase 5 report: general curve fitting

Date: 2026-10-14. Asked by Luis after the SciDAVis comparison (the Physics 2 teacher suggested SciDAVis). Code: `app/curvefit.js`, the `curve` task in `app/fit-worker.js`, settings in `app/project.js`. Checks: `tests/phase5-step1-nist.sh`, `tests/phase5-step2-reference.sh`, `tests/phase5-step3-curvefit-ui.sh`, all run by `bash scripts/check.sh`.

## Verdict

**The app now fits exponential, polynomial (degree 1 to 6), sine, Gauss and a free formula, with the same weighted and unweighted error handling as the line fit.** The numbers agree with NIST certified values to 6.5 to 9 digits, and with an independent solver on the models NIST has no problem for. It is a new tool "Kurvenanpassung" in the "Werkzeug wählen" menu. The line fit, the templates and everything built before are unchanged.

What this does not do: it does not make the app a copy of SciDAVis. FFT, smoothing, interpolation, integration, differentiation, convolution, 3D plots, matrices, bar and pie charts and scripting are still missing. Nobody has seen real Physics 2 task sheets yet, so whether these models are the ones her teacher needs is open.

## What a student gets

- Tool "Kurvenanpassung": pick Exponentialfunktion `a·exp(−x/τ)`, Polynom (degree 1 to 6), Sinus `A·sin(2π·x/T + φ)`, Gauß-Kurve `A·exp(−(x−μ)²/(2σ²))` or Eigene Formel. A checkbox adds an offset `c` to the exponential, Gauss and sine models.
- Own formula: write `x` and any parameter names, for example `a*exp(-x/tau)+c`; `+ − * / ^`, brackets, decimal commas, `pi`, and the functions exp, ln, log10, sqrt, sin, cos, tan, arctan, sinh, cosh, tanh, abs. Parameters are found by the tool in the order they appear (at most 10). Start values are optional (`a = 1; tau = 10`, default 1). Greek letters work as names.
- Result lines in HU format `(Wert ± u) Einheit`, a table with both errors (scaled by √(χ²/DoF) and unscaled), χ²/DoF or the sum of squares, the degrees of freedom, and the method in words. The fitted curve is drawn in the plot. The weighting checkbox and the error-method choice above the results apply to it.
- Out of date when data, weighting or the chosen model's settings change (not when only the degree of an unused model changes); undo, save and reload work. German and English.
- Refusals with a message that says what to do: unreadable formula, no x, no parameter, unknown function, too many parameters, fewer points than parameters, start values that give no numbers, a fit that found nothing it can stand behind.

## How the numbers were checked

| Model | Reference | Result |
|---|---|---|
| Free formula | NIST Misra1a, Misra1d, BoxBOD, Eckerle4, Lanczos3, Gauss1, ENSO, from both NIST start values | 13 of 14 starts: values 6.6 to 9 digits, standard errors 7.1 to 9 digits, residual sum of squares 9 digits. **BoxBOD start 1 is refused with a message** (NIST rates it hard; the fit stalls where the curve no longer depends on b2, and a number there would be wrong). |
| Gauss | NIST Eckerle4 (it is a Gaussian: A = b1/b2, μ = b3, σ = b2) | values 9 digits, μ and σ standard errors 9 digits, from the tool's own start values |
| Polynomial | NIST Pontius (degree 2), Wampler 1, 4, 5 (degree 5) | values 6.5 to 9 digits, standard errors 9 digits. Wampler 5 is the weakest at 6.5 digits. |
| Exponential, sine | **No NIST problem exists.** `tests/reference/curves.py`: own Levenberg–Marquardt with hand-derived derivatives and own matrix inverse, no SciPy and no NumPy | values, scaled errors, unscaled errors and χ² all 9 digits, on 3 exponential, 2 Gauss, 2 sine cases (weighted, unweighted, with and without offset, growth with τ < 0, uneven x) |
| Polynomial, weighted | same script, exact fractions | 9 digits |
| Page | each of the 9 reference cases entered through the page (paste, pick model, press the button) | all 9 pass; result lines hand-rounded for one case |

Full tables: `docs/nist-curve-results.md` (generated by the test). NIST's certified standard errors are for unweighted fits, so the weighted case (χ², unscaled and scaled errors) rests on the independent solver and the exact fractions, not on NIST. R is still not installed, so there is no R cross-check.

Two choices made while checking, both from a failing NIST set:
- **Complex-step derivatives.** Finite-difference derivatives gave only 5 digits on NIST Lanczos3. The tool now computes exact derivatives by evaluating the formula with a tiny imaginary step (works for every allowed function except `abs`, which falls back to finite differences). Lanczos3 went from 5 to 7.1 and 9 digits.
- **A refusal instead of a stalled fit.** With exact derivatives, BoxBOD from start 1 returned a finite but meaningless result (error on b2 of 10³⁷). A parameter whose error is a hundred million times its value now counts as "no result" and the student gets the message to try other start values or another model.

Safety: a formula is parsed to a tree and only numbers, `+ − * / ^`, `x`, parameter names and the listed one-argument functions are accepted; nothing else is evaluated (tested with `__import__` and attribute access). Numbers are converted to floats so `9^9^9` overflows at once instead of hanging.

## Speed

Apple M5, 16 GB, headless Chromium 145 on a local server, worker already running, best of three: exponential 30 points 5 ms, Gauss 250 points 5 ms, polynomial degree 6 with 1000 points 3 ms, free formula with 3 parameters 3 ms, NIST Gauss1 (8 parameters, 250 points) 7 ms, sine 30 points 29 ms, **sine 500 points 290 ms** (the frequency search for the start value is the slow part). The download did not change: the tool uses the same SciPy as before, plus about 28 KB of uncompressed code and texts (measured as the growth of the changed files).

## Not done, and known limits

- Results of nonlinear fits can depend on the start value. The tool says so under every nonlinear result and draws the curve so a wrong fit is visible. The built-in models find their own start values; the free formula starts at 1 unless the student gives values.
- No FWHM or other derived quantities for the curve models; the "Abgeleitete Größe" tool still works only with the straight line.
- Only one curve-fit result is kept (a new fit replaces the old one), like the other tools.
- Not checked against R. Not shown to a student. The real Physics 2 experiments are still unknown, so which models matter most is a guess.
